# 睡眠助眠声音（桌面 0.6.3）

2026-09-14。用户要求：「在宠物睡觉的时候加一段背景音乐，或者加一个打呼噜的声音，要助眠一点。」两种都做了，由用户在设置里选。

## 需求

- Momo 进入「睡觉」时自动播放助眠声音，醒来立刻停止。
- 声音要助眠：音量低、变化慢、没有突发瞬态，适合长时间循环。
- 主人可以选「摇篮曲 + 呼吸声」或「Momo 的打呼噜」，也可以选择安静睡觉。
- 不能和已有的音乐、语音回复叠在一起。

## 实现

新增 `app/sleep-sound.mjs`（`SleepAmbience`）。与 `app/sound.mjs` 的 `Soundscape` 一样，全部用 Web Audio 现场合成，**不引入任何音频文件**，因此没有版权与打包体积问题。

| 层 | 合成方式 | 作用 |
| --- | --- | --- |
| 垫底和弦 | 4 个正弦振荡器，频率在 4 个和弦间用 4.5 秒缓移，从不重新起音 | 温暖的底噪，永无咔哒声 |
| 摇篮曲旋律 | 五声音阶内的 8 音循环，每 2.6 秒一个正弦音，3.2 秒指数衰减 | 「哄睡」的旋律线 |
| 呼吸声 | 4 秒布朗噪声过低通（520 Hz），音量由 3.6 秒周期的正弦 LFO 推成 0 → 峰值 | 一呼一吸的起伏 |
| 打呼噜 | 两个失谐锯齿波（74 Hz / 74.4 Hz）过低通 340 Hz，叠加带通 140 Hz 的噪声，再用同相 LFO 开合 | 带颗粒感的低频鼾声 |

两种风格共用同一个呼吸周期（`BREATH_SECONDS = 3.6`），所以鼾声和呼吸永远同相。

配比（`SLEEP_MIX`，已导出以便测试与渲染脚本核对）：

- `lullaby`：和弦 .55、旋律 .5、呼吸 .07、鼾声 0
- `snore`：和弦 .09、旋律 0、呼吸 .31、鼾声 .31

锯齿与噪声进 `raspGain` 之前各自先衰减（`RASP_VOICE = .5`、`RASP_LEVEL = .8`、`RASP_NOISE_LEVEL = .3`）。这三个值不是装饰：第一版没设，两个满幅锯齿直接相加，把 `snore` 的整体峰值推到 1.5，满音量必然削波。

音源与状态的接线（`app/app.mjs`）：

- 进入「睡觉」→ `music.stop()`、必要时 `voice.stop()`、`playSleepSound()`。
- 醒来 → `stopSleepSound()`。
- 停止是 0.5 秒淡出 + 620 毫秒后才拆音源，避免爆音；之后再 `suspend()` 释放音频上下文。
- 播放是异步的，`playSleepSound()` 在 `await` 之后重新检查 `state.sleeping`，避免「点醒 Momo 的那一次点击」把助眠音又启动起来。
- 睡着时不允许开麦克风（`startVoice()` 增加与 S5 一致的「先叫醒我」拦截），否则 TTS 会盖在助眠音上。
- 关掉应用时宠物还在睡：浏览器禁止无手势自动播放，启动时先静默试一次，失败则挂一次性监听，主人第一次点击/按键时补上。
- `#pet-room` 上的 `data-sleep-sound`（`off` / `lullaby` / `snore`）是给测试和 CSS 用的可观察状态。

设置项（`设置 → 声音与麦克风 → 睡眠助眠声音`）：

- 风格下拉：摇篮曲 + 呼吸声 / Momo 的打呼噜 / 安静睡觉。
- 助眠音量：0–100，默认 30，与「音乐音量」互相独立。
- 「试听助眠声音」按钮。
- 两项都存 `localStorage['momo.sleep.sound.v1']`。

布局沿用项目既有约定：`select` 走 `.voice-input-settings` 的整行样式，滑块走 `.setting-row`（和「音乐音量」同一套），按钮走 `.form-actions`（和「键盘试听 / 重新读取」同一套）。

**第一版这里是有问题的**：滑块和按钮直接平铺，两者挤在同一行，按钮紧贴滑块右侧。经典 / 月光主题、桌面 / 移动宽度四种组合全都有这个问题——因为都是内联元素自然排列，没有出错也没有溢出，测试全绿，光看代码看不出来。截图自查才发现，已改成上面的结构。

## 实测：渲染成音频

`scripts/render-sleep-sound.mjs`（`npm run test:sleep-audio`）在真实 Chrome 里实时渲染音频图，用 `ScriptProcessorNode` 抓下总输出，降采样到 16 kHz 写成 WAV，并给出客观指标。**满音量 100 下峰值超过 0.95 会以非零码退出**——这是防止「调完混音悄悄削波」的硬闸门。

跑法：`node scripts/render-sleep-sound.mjs [秒数] [风格,风格] [音量]`，默认 `40 lullaby,snore 100`。产物在 `docs/sleep-sound-preview/`。

2026-09-14 在音量 100 下的结果：

| 风格 | 峰值 | 整体 RMS | 直流偏移 | 相邻采样最大跳变 |
| --- | --- | --- | --- | --- |
| 摇篮曲 + 呼吸声 | 0.7020（−3.1 dBFS） | −14.6 dBFS | −0.000041 | 0.1162 |
| Momo 的打呼噜 | 0.7523（−2.5 dBFS） | −18.3 dBFS | 0.002841 | 0.0864 |

这些数字能证明什么、不能证明什么：

- **没有咔哒声。** 16 kHz 采样下，880 Hz 正弦在幅度 0.7 时的理论单样本最大斜率是 0.7×2π×880/16000 ≈ 0.24，实测 0.116；`snore` 的内容在 340 Hz 以下，理论斜率上限约 0.10，实测 0.086。都落在「平滑信号」范围内，没有出现接近 1 的跳变——说明和弦缓移和 0.5 秒淡出确实没有产生不连续点。
- **不会削波。** 第一版 `snore` 在音量 70 下峰值就到 0.9456，换算成满音量是 1.35，必然削波。现在两种风格满音量都留了 2.5 dB 以上余量。
- **呼吸节奏是对的。** 40 秒窗口内 `snore` 的呼吸峰间隔 2.9–4.4 秒，均值约 3.5 秒（设定 3.6 秒）；`lullaby` 的旋律峰间隔稳定在 2.6 秒，与 `BELL_INTERVAL_MS` 完全一致。
- **幅度起伏是自然的，不是机械交替。** `snore` 呼吸峰高度的变异系数 20%（自然起伏），`lullaby` 只有 2%（几乎完全一致）。自相关在 40 秒窗口上给出 7.15 秒的「主周期」，那只是短窗口 + 幅度起伏造成的假峰；逐峰核对后不存在「每两下强弱交替」的结构问题。
- **两种风格峰值对齐了。** `snore` 的整体 RMS 比 `lullaby` 低 3.7 dB，这是低频内容占比高导致的，属于正常现象；峰值已经拉平到同一量级。

**这些数字不能代替耳朵。** 音色是否舒服、鼾声是否自然、会不会听腻，只有人听了才知道。

## 验证状态

已验证（2026-09-14 实跑）：

- `node --test tests/sleep-sound.test.mjs`：新增 7 项全部通过。覆盖非法值回退、和弦与旋律表有界且可循环、配比表完整且分层只在该出现的地方出现、音量取整与钳制、`off` 不创建音频上下文、自动播放被拦截时报错而不是假装在播、两种风格的音频图与淡出拆解生命周期。
- `node --test tests/*.test.mjs`：62 项，61 通过。唯一失败项 `voice assets are local, explicitly allowed...`（`tests/server.test.mjs`）是因为本机 `node_modules/@ricky0123/vad-web/dist/bundle.min.js` 不存在（需要完整 `npm ci` 与 `npm run voice:setup`），与本次改动无关。
- `playwright test`（完整界面套件，真实 Chrome）：46 / 46 通过。其中 4 条覆盖这个功能：
  - `sleep ambience follows sleeping, the setting and waking`：睡着后 `data-sleep-sound` 变成 `lullaby`（说明 Web Audio 真的起来了）、播放中切到 `snore` 立刻生效、醒来回到 `off`、选「安静睡觉」后睡着也不播放、风格与音量刷新后仍然保留。
  - `a pet that was already asleep at launch gets the ambience back`：注入一个「没有用户手势时 `resume()` 不起作用」的假 `AudioContext` 来模拟自动播放拦截，断言启动时是 `off`、第一次点击后变 `lullaby`。这条把「关掉应用时宠物还在睡」的恢复路径钉死了。
  - `a sleeping pet refuses the microphone and keeps the ambience playing`：睡着时点麦克风只说「先叫醒我」、不申请麦克风（`voiceTracks.length === 0`）、助眠音不受影响。
  - `putting a talking pet to sleep ends the session and hands over to the ambience`：语音进行中按「睡觉」，会话结束、轨道全部停止、助眠音接手。
- `npm run test:sleep-audio`：满音量渲染两种风格，峰值均未超过 0.95；具体数字见上一节。
- **设置面板做过视觉自查**：在经典 / 月光主题、1280 宽 / 390 宽四种组合下截图比对，并与既有的「键盘操作音效」面板对照，确认按钮位置、滑块位置和整体节奏一致；移动宽度无横向溢出。这一步抓到了上面那个「滑块与按钮挤在同一行」的布局问题。
- 新增 `server.mjs` 白名单守卫测试：遍历 `app/` 下所有 `.mjs/.css/.html/.svg` 并断言都能取到 200。这条是为本次改动加的——静态白名单是手写的，新增模块忘了登记就会静默 404，写这个功能时确实漏了一次。

未验证：

- **没有实际听过**。客观指标只能排除削波、咔哒、节奏错误这类问题；音色是否舒服、鼾声是否像鼾声、长时间听会不会腻，必须由人判断。这是当前最大的空白。`docs/sleep-sound-preview/` 里的两个 WAV 就是为此准备的，听完再决定要不要调 `SLEEP_MIX` 或换和弦。
- 没有在真实助眠场景（戴耳机循环 30 分钟以上）观察听感疲劳。可以算一个数字作为参考：垫底和弦 9 秒一换、4 个和弦共 36 秒一轮，旋律 8 音 20.8 秒一轮，两者的最小公倍数是 936 秒——也就是说**确定性音层（和弦 + 旋律）要 15.6 分钟才会回到完全相同的相位**；噪声层每次运行都是新的随机序列，所以整段信号实际上不会精确重复。这是算出来的，不是听出来的。
- 没有实测打包后的 Electron 是否也需要「等第一次点击」这条恢复路径。`desktop/main.cjs` 里设了 `autoplayPolicy:'no-user-gesture-required'`，理论上不需要；即使需要，那条路径已被上面第二条界面测试用模拟拦截的方式覆盖。
- 语音与睡觉的交互只在**模拟的**语音会话上验过（`tests/ui/voice.spec.mjs` 里的替身 WebSocket 与 `getUserMedia`），没有连真实 VTuber 服务跑过。没有验收「语音正在播回复时按睡觉」这种最细的时序：当前实现是先 `voice.stop()` 再起助眠音，理论上不会有重叠，但没有实测。
- 渲染脚本抓的是 headless Chrome 的音频图，不是真实扬声器输出；它验证的是信号本身，不是设备播放链路。
