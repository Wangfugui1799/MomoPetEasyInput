# EasyInput 无线语音：首次配置与日常使用

桌面版本 0.6.3 / 固件 0.6.0，更新于 2026-09-12。方案是 **BLE 配网和按键控制 + Wi-Fi 麦克风 + Mac 播放回复**，不是把开发板配成 macOS 系统蓝牙耳机。USB 麦克风仍保留。当前按键操作见 [S5 按键留言](S5-VOICE-MESSAGE.md)。

当前开发板已完成 0.6.0 应用区烧录、写入校验、正常启动和 Momo 连接验证。用户反馈无线首轮后断开，0.6.1 是桌面端连续对话修复，不需重新烧录或重新绑定。无线真人三轮仍待修复版实测；USB 真人三轮用户已确认通过。其他仍运行旧固件的设备不能通过更新 Mac 应用直接获得无线音频。

## 先准备

- EasyInput V2.0 / AI Keyboard V2.1，升级到 Momo 0.6.0 固件。烧录需另外明确确认；不会因运行应用自动烧录。
- Momo 0.6.3 Mac 桌面版；浏览器预览不提供无线音频接收。
- 普通 2.4 GHz WPA2/WPA3 Personal Wi-Fi。密码为 8–63 个可打印 ASCII 字符，名称最多 32 个 UTF-8 字节。企业 Wi-Fi、网页认证、开放网络不支持。
- Mac 与板子处于可互通的局域网；Mac 可以接网线。关闭路由器客户端隔离，避免访客网络或 VPN 地址。
- 按 [语音安装教程](VOICE-SETUP.md) 配好本地后端、识别模型和自己的 AI 密钥。`npm start` 或双击 Momo 不会自动启动后端；源码环境可运行 `npm run start:voice` 同时启动。

当前独立应用位于 `dist/s5-message/Momo-darwin-arm64/Momo.app`，包含 S5 按键留言、连续模式修复和自动接收，仅 Apple Silicon 本机开发包，未进行 Developer ID 公证。启动前退出旧 Momo，避免它占用 4784、4786 或 USB 串口。不要同时开两个版本控制同一块板；保留原应用数据，不必重新绑定或填写 Wi-Fi 密码。

## 首次配置：只需要一次 USB 信任绑定

1. 用原生 USB Serial/JTAG 数据口连接开发板，不要用 UART 桥接口。在 Momo 顶部连接 EasyInput，等待协议握手成功。
2. 打开设置，在「EasyInput 无线麦克风」点击「通过 USB 绑定这台 Mac」。它会生成新的随机密钥，板端保存到 NVS，Mac 用系统安全存储加密保存。重新绑定会替换旧绑定，旧 Mac 需要重新绑定才能接入。
3. 在「Mac 局域网地址」选连接同一路由器的地址，点击「开启无线接收」。接收服务仅监听选定地址的 TCP 4786。macOS 防火墙询问时，允许 Momo 的局域网入站连接；不要关闭整个防火墙，也不需要路由器端口映射。
4. 关闭设置，点击顶部连接按钮断开应用内 USB，再点击「蓝牙连接」。从 Momo 设备选择框选中这块 EasyInput；无需到 macOS 蓝牙设置将其配成音频设备。此时数据线可保留供电，但音频路径将使用 Wi-Fi。
5. 回到设置，填写 Wi-Fi 名称与密码，点击「通过蓝牙配置 Wi-Fi」。应用会加密发送网络信息和 Mac 地址，发送后清空密码框。一般等待数秒；15 秒仍未就绪会给出排查提示，可以刷新或重试。
6. 等待「EasyInput 无线语音已连接」，选择语音输入「EasyInput · 板载麦克风（Wi-Fi）」。顶部的 BLE 已连接只表示控制链路，无线设置中的状态才表示音频链路。
7. 开启板子电源、确认电池有电后拔掉 USB。按 S5 开始录音，看到录音提示后说话，说完再按 S5 发送；回复从 Mac 播放，回复后等待下次 S5。聊天活动中短按旋钮只显示聊天框。实体 S5/旋钮需要应用内 BLE 控制连接。

如果先前语音正在进行，更换输入、关闭接收或重新配网会停止当前语音。连接成功不会偷偷开始收音，仍需你主动开启聊天。

## 日常使用

1. 启动本地语音后端与 Momo，板子开机。
2. 首次选择正确的 Mac 地址并「开启无线接收」；0.6.2 会保存这个选择，以后打开 Momo 自动恢复接收。新用户未开启过则不监听。手动「关闭无线接收」会同时取消下次自动恢复；退出应用只停止当前接收，不取消已保存的选择。
3. 等待无线语音已连接。需要八键和旋钮控制时，另外连接顶部 BLE；单纯用鼠标开语音不依赖 BLE 持续连接。
4. 选择 Wi-Fi 输入并开始聊天。选定输入会保存，不会自动改成电脑麦克风。

Wi-Fi 配置保存在板端，日常无需再填密码，也无需 USB。Mac DHCP 地址变化、换路由器时，刷新地址、关闭再开启接收，然后通过 BLE 重新配网。可以在路由器上为 Mac 保留固定 DHCP 地址；本版没有自动局域网发现。

板子开机自动读取已保存的 Wi-Fi 名称、密码和 Mac 地址并尝试连接；Momo 须保持运行，Mac 不能休眠。若 Momo 启动时原地址尚不可用或端口被占用，会明确提示，不会改为监听所有网络；联网后重新开启接收即可。自动接收配置保存在 Mac 应用数据目录的 `wireless-receiver.json`，仅含启用状态和 Mac 地址，不含 Wi-Fi 密码或绑定密钥。连接就绪不等于开始聊天，麦克风仍由用户主动开启。

## 停止、断线与隐私

- 关闭麦克风或退出应用会停止采集；模型思考和回答播放时暂停采集，但不结束会话。S5 模式回复后等待下次 S5 才收音；聊天框麦克风按钮开启的旧连续模式才会自动恢复「正在听」。
- 接收端会暂停网络读取来吸收短暂音频积压，不直接当作断线；真正断网、帧丢失、超过缓冲上限或麦克风租约超过 3 秒仍会安全停止。网络重连不会自动恢复录音；需重新开启。
- USB 和 Wi-Fi 只有一个能持有麦克风，不会相互续租、停止或抢占对方正在进行的录音。
- BLE 网络配置采用带随机挑战的 AES-256-GCM；音频使用绑定密钥派生的 TLS 1.2 ECDHE-PSK-CHACHA20-POLY1305。不是裸 TCP 音频，也没有公开无认证的语音接口。
- 原语音后端仍只监听 `127.0.0.1:12393`，不要改为公网监听。语音识别后，文本和历史依然按后端配置传给 AI 服务。
- 板端 NVS 没有启用 Flash 加密，不能防止有物理读取能力的人提取密钥和 Wi-Fi 密码；不要将本版视为已通过产品安全认证的设备。

## 常见问题

| 现象 | 检查 |
| --- | --- |
| USB 绑定按钮提示需要新固件 | 确认实板已更新 0.6.0、插原生 USB 数据口、应用已完成握手；旧固件/UART 桥不能绑定 |
| 没有 Mac 地址可选 | Mac 先接入局域网，再刷新；只允许私有或链路本地 IPv4，不支持 IPv6-only |
| 提示先连接蓝牙 | 关闭设置，断开应用内 USB，再点顶部蓝牙连接，完成后回来配网 |
| 配网验证失败或设备不一致 | 确认 BLE 和 USB 绑定的是同一块板；若在另一台 Mac 绑定过，需 USB 重新绑定 |
| Wi-Fi 已连接，等待 Momo | 检查无线接收已开启、Mac IP 未变、TCP 4786 未被防火墙阻止、路由器无客户端隔离 |
| 网络断开、持续重试 | 检查 2.4 GHz、密码、板子供电和信号；重填配置并等待状态结果 |
| 已连接但没有 AI 回复 | 分别检查语音后端 `npm run voice:check`、输入选项、模型配置和麦克风开启状态；网络连接成功不等于识别链路成功 |
| 对话断线后不再听 | 本版设计为断线停止；重新连接后手动开启语音，不会自动恢复 |
| 首轮回答后提示 EasyInput 已断开 | 先使用桌面 0.6.1，确认选择 Wi-Fi 输入；普通回合应自动恢复倾听。若仍断开，请记录新提示中的「积压」「心跳超时」或「确认超时」及无线设置状态，以区分网络、供电与接收端问题 |
| Mac 安全存储绑定无法读取 | 在当前 macOS 用户下重新 USB 绑定；不要复制明文密钥或把绑定文件提交 Git |

## 验收与开发

先查看 [需求与边界](WIRELESS-VOICE-REQUIREMENTS.md) 和 [软件验证记录](WIRELESS-VOICE-VALIDATION.md)。实板最终验收必须：拔 USB 后连续真人三轮；同时使用按键与旋钮；关闭/重开接收、Wi-Fi 断连和断电重连；确认无自动收音、无电脑麦克风回退，并记录延迟和回声。

编译使用 ESP-IDF 5.5.5 和体积优化，不修改 GPIO、BOOT、共享电源或分区：

```sh
source /path/to/esp-idf/export.sh
idf.py -C firmware -B "$PWD/firmware/build-wireless" -D SDKCONFIG="$PWD/firmware/build-wireless/sdkconfig-release" build
```

此命令只构建。已有设备升级时先核验芯片、MAC、端口及分区，再确定最小写入范围，不能整片擦除。
