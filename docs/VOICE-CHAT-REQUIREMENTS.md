# Momo 语音聊天试用版需求 V0.1

日期：2026-09-08
状态：需求确认稿，尚未实现。

## 1. 这版只解决一件事

用户通过电脑麦克风对 Momo 说话，Momo 能听懂、回复，并通过电脑扬声器说出来。

保留现有 Momo 形象，使用本机 Open-LLM-VTuber 作为语音对话后端。先把真实对话跑通，不扩展硬件控制或复杂的会话管理。

## 2. 最简单的使用流程

1. 先启动本机 VTuber 服务，再打开 Momo 的聊天窗口。
2. 在“开始聊天”界面点击“打开麦克风”，首次使用时允许访问电脑麦克风。
3. 直接对宠物说话；系统自动判断说话结束并发送，不需要逐句点击发送。
4. 窗口显示识别出的文字和 Momo 的回答；电脑扬声器使用后端当前默认的 TTS 声音播放回答，前端不另选声音、不调用系统朗读替代。
5. 回答结束后自动恢复倾听，用户可以直接说下一句，无需再次开启麦克风。
6. 再次点击按钮“关闭麦克风”结束语音聊天，停止采集、发送和播放，丢弃未提交录音与迟到音频；关闭聊天窗口同样结束。

界面只需要麦克风开关、简单状态提示和对话文字。麦克风默认关闭，开启后显示“正在听”，处理时显示“正在想”，播放时显示“正在说”。首版实时聊天指开启后自动轮流对话：宠物思考和说话时暂停接收新的语音轮次，播放结束后自动恢复，避免把扬声器里的回答再次当成用户输入；暂不支持同时说话或语音抢话。服务未启动、麦克风未授权或请求失败时，显示明确原因，允许重新尝试。关闭聊天时停止录音和播放。

## 3. 首要技术关注：前后端必须匹配

不能只做一个录音界面，也不能把 WebSocket 连通当作聊天成功。需要直接按照当前本机 VTuber 的实际协议编写 Momo 前端适配代码，并用真实后端验证。

| 核对项 | 要做到什么 |
|---|---|
| 连接与初始化 | 连接 `/client-ws`，完成后端要求的初始化后才允许发送 |
| 麦克风音频 | 将浏览器采集的音频转换成后端要求的采样率、声道及采样数组；不能直接发送不兼容的录音文件字节 |
| 自动断句与输入消息 | 接入语音活动检测（VAD），自动判断一句话结束；按当前后端实际支持的音频/VAD 消息流程发送，一段话只触发一次回答。开发时确认采用前端断句发送 `mic-audio-data` / `mic-audio-end`，还是后端 `raw-audio-data` 检测流程，不得同时触发两套流程 |
| 返回文字 | 根据后端实际消息显示识别结果和回答，不能靠猜字段拼接 |
| 返回语音 | 正确解码后端返回的 Base64 WAV；分段回答按顺序播放，不重叠、不漏播 |
| 播放与结束 | 按后端要求发送播放通知，确认一轮结束后自动恢复倾听；静音或背景噪声不应持续触发空回复 |

已查看的源码中，ASR 接口默认采样率为 16 kHz，音频输入使用采样数组；音频输出消息为 `audio`，含音频和显示文字。开发时仍需核对当前实现的完整字段和消息顺序。

Momo 当前没有真正的麦克风录音功能，Electron 权限策略及 macOS 麦克风用途说明也需要补齐。现有 `speak()` 只改变气泡文字，不能当作已实现语音播放。

## 4. 实现顺序

1. **先验证前后端对接**：用 Momo 发送文字到实际 VTuber 后端，收到回答并播放声音，确认消息与播放流程匹配。
2. **再接电脑麦克风**：增加麦克风开关、自动断句、格式转换和发送，跑通“说话 → 识别 → 回复 → 出声”。
3. **最后实际试聊**：连续进行三轮语音聊天，修正重复回复、音频重叠或无法开始下一轮等问题。

文字输入是验证接口的中间步骤，最终交付必须包含真实麦克风语音聊天。

## 5. 验收：实际聊上天

- 进入“开始聊天”界面，只点击一次“打开麦克风”，使用电脑麦克风说一句中文，停顿后自动得到回答。
- 能看到对应的识别文字和真实模型回答，电脑扬声器播放后端默认 TTS 声音。
- 无需逐句点击按钮即可连续完成三轮；无重复发送、重叠播放、将宠物声音识别成用户输入或卡在等待状态。
- 关闭麦克风或聊天窗口后停止采集和播放，不再继续提交或播出迟到回复。
- 服务不可用或麦克风被拒绝时，界面能说明原因。
- 前后端验证记录说明使用的服务版本、音频格式及实际跑通的消息流程。

HTTP 200、WebSocket 连接成功、模拟测试通过都不能替代上述真实试聊。

## 6. 本版边界

只用电脑麦克风与扬声器，后端先手动启动。暂不做 EasyInput 按键接入、固件修改、未开启麦克风时的后台监听、语音打断、历史恢复、角色系统扩展或后端打包。

当前后端配置使用 DeepSeek 和 Edge TTS，需要联网。保留 Momo 现有外观与其他功能；语音对话走 VTuber，不能同时调用原有文字接口造成重复回答。
