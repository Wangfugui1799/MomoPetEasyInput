## 2026-09-11 桌面 0.6.1 连续对话修复

- 用户确认 USB 连续真人三轮已通过；无线首轮结束后提示「EasyInput 已断开，键盘麦克风已关闭」。这是用户现场反馈，不是本轮自动化结果。
- 复现了桌面接收端误断开：同一同步接收循环集中交付 96 帧，渲染器尚未来得及 ACK，旧实现达到 64 帧就关闭 TLS。回归测试在旧实现失败，在修复后通过。该缺陷与提示一致，但尚未证明它是用户现场的唯一原因。
- 改为最多 64 帧在途 IPC，加最多 128 帧当前回调余量；达到高水位暂停 TCP 读取，ACK 后按序排空，低于 32 帧恢复读取。不丢弃有效帧，不无界缓存；超限仍安全断开。真实断线会清空旧队列，不自动重新收音。
- 回合结束等待 `mic_stop` 成功确认；下一轮不会越过未完成的停止。断线提示透传积压、心跳超时、确认超时等可区分原因，不记录音频或凭据。
- `npm test`：42/42 通过，包含延迟停止、取消、错误传递、突发接收、缓冲上限及重连清理。
- Electron 自带 Node 运行 `tests/wireless.test.mjs`：8/8 通过。真实 TLS + 延迟 80ms ACK 连续三轮，每轮 160 帧按序完整接收；板端由电脑 TLS 客户端模拟。
- 完整界面回归：25/25 通过，包含原 USB 路线、Wi-Fi 三轮及停止确认延迟 750ms 的三轮自动恢复；VAD、硬件与语音后端为模拟。
- 桌面修复包：`dist/wireless-continuous/Momo-darwin-arm64/Momo.app`，0.6.1 / arm64。保留原 `dist/wireless` 包，未覆盖运行中的应用。
- 原生修复包冒烟检查通过：使用独立临时配置和 4788 端口，八键、无线设置、默认不监听、IPC 拒绝无效操作与渲染隔离均通过，页面错误为 0；未连接用户开发板或启动收音。
- 本次只修改桌面与测试/文档，没有修改固件、GPIO、共享电源或 BOOT，也没有烧录、提交或推送 Git。板端仍使用已烧录的 0.6.0。

实机复测：退出旧 Momo，启动修复包，开启无线接收，明确选择「EasyInput · 板载麦克风（Wi-Fi）」并等待连接；无需重新绑定。板子独立供电、拔 USB 后说三轮，每轮回答完成应自动恢复「正在听」，会话保持开启。若仍失败，记录具体错误与无线设置状态，继续排查供电、网络及板端。此项完成前不能宣称无线真人连续对话已验收。
