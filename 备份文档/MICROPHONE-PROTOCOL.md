# Momo 键盘麦克风协议 v1

实施版本 0.5.0，2026-09-08。保留 `momo-easyinput/1` 的按键、旋钮、音效与电量消息；音频能力可选，旧固件仍可控制宠物。

## 采集与独占

板载 I2S1 RX 使用 GPIO9 BCLK、GPIO10 WS、GPIO11 DIN，16 kHz、32 位左声道时隙。当前转换取输入字的高 16 位；时隙、灵敏度及实际输出格式待实板确认。操作音使用 I2S0 TX。麦克风启停不切换 GPIO8 共享电源。

采集只在有效租约内开启。租约由连接类型（1 原生 USB、2 BLE）和会话编号共同确定，另一个所有者不能抢占；每 500 ms 续期，固件 2000 ms 未续期停止。结束、断连、取消通知均清理相应所有者；USB 无法送达 stop 时依靠租约到期。启动、停止可重复发送；过期租约不可直接续期，必须重新 start。

每帧 20 ms / 320 样本，独立 IMA ADPCM 编码，共 176 字节。固件待发送队列最多三帧；拥塞丢旧帧，序号继续递增。应用等待首个匹配会话的音频帧后才显示「我在听」，不能用 hello 或控制确认代替音频。

## 音频帧

所有多字节整数为小端序。

| 偏移 | 长度 | 字段 |
| --- | --- | --- |
| 0 | 1 | 版本，固定 1 |
| 1 | 1 | 编码，固定 1（IMA ADPCM） |
| 2 | 4 | 非零会话编号，应用限制为 1–2147483647 |
| 6 | 4 | 帧序号，从 0 开始，无符号 32 位回绕 |
| 10 | 2 | 样本数，固定 320 |
| 12 | 2 | 首样本 / 初始预测值，有符号 PCM16 |
| 14 | 1 | 初始步长索引，0–88；本版编码器取 32 |
| 15 | 1 | 保留，固定 0 |
| 16 | 160 | 后续 319 个样本的 4 位 ADPCM 编码，低半字节在前；最后高半字节未使用 |

应用丢弃旧会话、重复和倒序帧；孤立缺失最多三帧用静音补时，连续缺失更多或 1400 ms 无音频则报错结束收音。首次启动 2400 ms 未收到音频也报错，不能假装处于倾听状态。

## 原生 USB

需 ESP32-S3 原生 USB Serial/JTAG（VID 303a、PID 1001），且 hello 声明 `mic:true`。UART 桥仍可控制按键，但不承载语音。原生 USB 的 115200 设置不等于 UART 桥吞吐；音频约每秒 50 条 JSON Lines。

命令示例：

```json
{"protocol":"momo-easyinput/1","type":"mic_start","session":123}
{"protocol":"momo-easyinput/1","type":"mic_lease","session":123}
{"protocol":"momo-easyinput/1","type":"mic_stop","session":123}
```

控制回执：`type:mic_state`，带 `session`、布尔 `ok`、`error`（`none`、`mic_busy` 或 `mic_unavailable`）。音频消息：`type:mic_frame`，`data` 为上述 176 字节帧的 236 字符 Base64。消息以换行分隔，并在每条前加换行以从部分写入恢复；维持现有 512 字符行上限。应用发送队列上限为八条，与音效命令共用有序写入。

## BLE

原有服务 `4d4d0000-0000-0000-0000-000000000001` 及事件特征 `…0002` 不变。

- `4d4d0000-0000-0000-0000-000000000003`：音频 Notify。
- `4d4d0000-0000-0000-0000-000000000004`：控制 Read / Write with response。

控制读取两字节 `[1, ready]`。写入六字节 `[1, op, session LE32]`，op 为 1 start / 2 lease / 3 stop。写入失败是明确错误，不能视为启动成功。start / lease 要求已订阅音频且 MTU ≥ 100；首选 MTU 247，实际协商由平台决定。

每个音频通知以五字节 `[0xa1, seqLow16 LE, part, count]` 开头，再附帧内容。part 从 0 开始，顺序拼接；全部字节必须恰为 176。组帧超时 250 ms、乱序、缺段或序号不符时丢弃。发送不重试以免阻塞原有输入，实际无线吞吐和按键并行延迟待实板测试。
