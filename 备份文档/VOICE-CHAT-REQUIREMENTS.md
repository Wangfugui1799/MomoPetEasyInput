# Momo 桌宠实时语音聊天需求文档

版本：V0.3 评审稿（S5 选择、旋钮确认，聊天与其他活动并行）  
日期：2026-09-08  
目标项目：NewEP / Momo，需求基线 0.4.0，实施版本 0.5.0  
参考项目：本机 Open-LLM-VTuber 代码  
状态：已获开发授权，0.5.0 已实现并进行电脑测试与构建；未烧录、未完成真实模型和声学验收。实施结果与尚未达标项见 [语音验收记录](VOICE-CHAT-VALIDATION.md)。本文保留原定产品目标，不以实现代替验收。

## 1. 产品目标

用户先按 EasyInput 的 S5「聊天」键选择聊天，再按下旋钮确认开始，即可实时对 Momo 说话。单独按 S5 不开启麦克风。Momo 听完后以自己的口吻回答，同时显示文字、从 Mac 播放语音，并通过现有宠物形象表现倾听、思考和说话状态。键盘连接时使用键盘麦克风，未连接时使用 Mac 麦克风；没有键盘也能通过屏幕按钮开始。一次开启后可以连续聊多轮，不需要每句话重新按键，聊天期间仍可按其他按键、旋转和按下旋钮使用对应活动，选择其他活动不结束会话。整个功能由当前 NewEP / Momo 项目提供。

示例：按 S5 → 界面选中聊天并显示「按旋钮开始聊天」→ 按下旋钮 → 显示「我在听」→ 用户说「今天有点累」→ Momo 用语音回应 → 按 S1、旋转选择食物、按旋钮喂食，聊天继续 → 用户接着说话，Momo 延续上下文回答 → 点击常驻的「结束聊天」结束。

本稿中的“实时”指可连续、多轮、低等待感的语音交互。基础处理链为语音识别 → 语言模型 → 语音合成；首版不要求更换为原生语音到语音模型，也不把逐字识别字幕作为必备能力。

## 2. 已确认需求与建议默认值

| 类型 | 内容 |
| --- | --- |
| 用户明确要求 | 参考 Open-LLM-VTuber 的功能与代码，升级现有桌宠聊天；S5 选择聊天后按旋钮开始实时对话，且不影响其他按键；本轮只交付需求文档 |
| 用户已确认的交互 | S5 只选择聊天，旋钮按下确认开始；聊天与其他活动并行，其他按键保留原功能 |
| 建议退出方式 | 常驻「结束聊天」按钮；选中 S5 聊天活动时长按旋钮结束；单独再次按 S5 不结束 |
| 用户已确认的收音规则 | 键盘已连接时使用 EasyInput 板载麦克风；键盘未连接时使用 Mac 麦克风 |
| 用户已确认的播放位置 | Momo 回复由 Mac 播放，默认 Mac 扬声器；不要求键盘扬声器播放回答 |
| 用户已确认的实现边界 | 参考 Open-LLM-VTuber 的代码思路，在 NewEP / Momo 内重新实现语音聊天；不启动、不连接、不依赖该项目的运行服务 |
| 建议人格 | 中文、温暖、简短、低压力的日常陪伴；继续使用 Momo 身份 |
| 建议记录策略 | 当前打开期间保留上下文，默认不持久保存聊天原文或原始录音；养成日记只记录概述 |

键盘麦克风采集与上传属于首版范围。当前按键连接不能证明键盘麦克风可用；需要增加采集、音频通道及能力握手。播放保持在 Mac，板载扬声器继续承担现有操作音，不承担 Momo 回答。

## 4. 首版范围

### P0：首版必须交付

- S5 选择聊天、旋钮确认开始；屏幕选择聊天后点击开始提供等价入口。
- 聊天状态独立于当前活动；切换活动不结束对话，旋钮操作只交给当前活动处理。
- 键盘连接时板载麦克风收音，未连接时 Mac 麦克风收音；Momo 回答在 Mac 播放。
- USB 与 BLE 的键盘麦克风上传、设备能力检测和会话期间的音源切换。
- 中文语音输入、自动判断一句话结束、识别文本展示。
- 有上下文的模型回复、分段语音播放及相应字幕。
- 一次开启后连续对话，支持自然语音打断与常驻的屏幕打断按钮；旋钮手动打断仅在聊天活动被选中时有效。
- Momo 的倾听、思考、说话、结束和异常状态反馈。
- 麦克风权限引导、项目内语音模块就绪检测、模型连接检测、超时与断连处理。
- 只启动 Momo 即可使用；Open-LLM-VTuber 未运行、未安装或目录不存在均不影响功能。
- 保留文字聊天入口，语音和文字使用同一会话上下文。
- 明确结束聊天、关闭应用窗口或系统睡眠后清理采集与播放；收起聊天面板、切换活动不结束会话。设备异常按音源切换规则处理。
- USB、BLE 和屏幕入口分别验收，不把连接成功当作聊天成功。

### 后续范围

键盘扬声器播放 Momo 回答、跨重启长期记忆、角色和音色市场、逐字实时识别字幕、精细口型、唤醒词、视觉输入、屏幕与摄像头感知、MCP 工具调用均不作为首版必要条件。

首次配置及模型准备允许在 Momo 设置阶段完成；日常已准备好时，开始聊天只需按 S5 再按旋钮。语音流程、依赖与生命周期由 NewEP / Momo 管理，不要求用户启动另一个项目。若某个本地模型必须使用辅助进程，该进程也必须属于 Momo 的交付和管理范围，不能包装启动 Open-LLM-VTuber。

## 5. 按键与会话规则

活动选择与语音会话分别管理。语音可以在喂食、摸摸、训练、探索、装扮或音乐活动中持续运行；聊天不得全局占用旋钮，也不得用模态弹窗拦截实体键。一次输入只执行当前活动的一个动作。

| 当前状态 / 操作 | 预期行为 |
| --- | --- |
| 未聊天，按 S5 | 只选中聊天活动，显示「按旋钮开始聊天」；不开麦，不提交消息 |
| 选中聊天，未开启会话，按旋钮 | 检查权限与模型、开始采集，成功后显示「我在听」 |
| 正在准备，重复按旋钮 | 忽略重复开启，不创建第二会话；需要取消时使用明确的结束入口 |
| 会话中再次按 S5 | 只切回聊天活动并显示现有会话，不结束、不重新开启 |
| 会话中按 S1～S4、S6～S8 | 正常选择对应活动，语音继续，按键本身不结束会话 |
| 选中其他活动时旋转 / 按下旋钮 | 按原规则选择和确认该活动，不调聊天音量、不提交语音、不打断回复 |
| 选中聊天，Momo 正在说话，旋钮短按 | 打断当前回复，清空未播片段，回到倾听 |
| 选中聊天，正在思考，旋钮短按 | 取消本轮等待，回到倾听 |
| 选中聊天，正在倾听，旋钮短按 | 有有效语音时手动结束本句并提交；空输入不提交 |
| 选中聊天，未开启会话，旋转旋钮 | 沿用聊天话题选择；仅选择不采集音频 |
| 选中聊天，会话活跃，旋转旋钮 | 建议调节 Momo 回复音量，每步 5%，限于 0～100%；其他活动的旋转含义不变 |
| 选中聊天时长按旋钮 / 点击常驻「结束聊天」 | 明确结束会话、清理采集与播放，保留本次可见文本 |
| 选中其他活动时长按旋钮 | 保留该活动的取消或返回动作，不作为聊天全局退出键 |
| Esc / 收起聊天面板 | 只取消当前活动选择或收起面板；会话仍在时保留醒目的收音状态与结束按钮 |
| 选中 S8 睡眠活动 | 只切换活动，聊天继续；确认睡眠的处理见下方例外规则 |
| 宠物已睡眠，按 S5 | 只选择聊天；沿用现有规则，确认时提示先用 S8 唤醒，不提前开麦；唤醒后再按 S5 与旋钮开始 |

建议例外：用户在 S8 下明确确认“睡觉”时结束语音会话，按钮提前显示「睡觉并结束聊天」；仅选择 S8 不结束。该项是待评审的产品建议，不作为用户已确认内容。电脑系统睡眠、关闭应用或明确结束聊天仍须清理音频资源。

聊天视图必须允许原有活动操作，切到其他活动后以常驻状态条显示「聊天中」及当前麦克风来源。其他活动的反馈可以显示在活动区，不能覆盖聊天字幕、清空对话或取消模型请求。音乐和语音并行规则见第 6.1.1 节。

设置等具有未保存内容的编辑窗口沿用原有保护行为，但语音会话本身不扩大拦截范围。不得因为聊天正在运行就使原本可用的按键或旋钮失效。

S5 长按不增加新动作。旋钮长按沿用已有 `long_press` 事件，按当前活动解释。现有输入事件可以表达两步开始；键盘麦克风采集、启停与音频上行仍需新增固件能力。

硬件已连接且 Momo 存活时，S5 在后台或最小化状态下只恢复窗口并选择聊天，旋钮确认才开始；已开启会话不因窗口恢复而重启。真实行为须在打包应用中验证。退出应用后按键自动启动应用不在本期范围。

## 6. 语音体验

### 6.1 开始与收音

首次使用提供语音设置，展示实际输入设备、Mac 播放设备、权限状态、服务状态和一次测试入口。默认使用 Mac 内置扬声器；若用户明确改为耳机则尊重其选择。电脑无键盘时默认使用 Mac 内置麦克风，不随意选取其他外接麦克风。所需权限未获准或用户取消时，保持未收音，并提供文字入口。

### 6.1.1 自动音源选择与切换

“键盘已连接”指 Momo 已建立并验证的 USB 或 BLE 连接，不是系统显示已配对，也不是仅有 USB 供电。语音启动时还须确认该键盘报告麦克风能力、完成采集启动并收到有效音频帧。一次只能有一个有效输入源，避免两路重复识别。

| 场景 | 收音规则 |
| --- | --- |
| 开始聊天，未连接键盘 | 申请并使用 Mac 麦克风；通过屏幕按钮开始 |
| 开始聊天，键盘已连接且麦克风就绪 | 使用键盘麦克风；Mac 麦克风不采集 |
| 已连接旧固件或键盘麦克风故障 | 显示「键盘已连接，但麦克风不可用」，不把 Mac 收音伪装成键盘收音；提供用户主动选择的临时 Mac 模式 |
| 会话中连接键盘 | 暂停提交，等待键盘音频就绪后停 Mac 收音，再切到键盘；界面显示「已切换到键盘麦克风」 |
| 会话中键盘断开 | 停用键盘流，切到 Mac 麦克风并显示切换提示；Mac 权限不可用时暂停并引导授权，不假装仍在听 |
| 会话中键盘在线但音频中断 | 暂停并提示键盘麦克风异常，不自动把它当作未连接；允许重试或明确选择临时 Mac 模式 |
| 非会话期间连接 / 断开键盘 | 只更新下一次使用的音源，不开启任何麦克风 |

切换时丢弃尚未提交的半句并提示「麦克风已切换，请重说刚才那句」，不把两个设备的样本拼为一句。已经提交的轮次保留；切换中的提示和音频不得制造新轮次。切换完成前显示「正在切换」，不能显示「我在听」。

用户本轮确认了按连接状态选择音源；会话期间的上述自动切换是本稿提出的交互细化。首次设置应明确告知“键盘断开后会切到 Mac 麦克风”，并提供结束入口。

只有界面明确进入「我在听」才表示可以开始说话。S5、旋钮与其他按键的操作音不能被当作用户发言；对提示音采用采集门控或回声处理。S7 音乐继续按原规则播放或停止，不能因为聊天被禁用或自动停止；语音回复期间可临时降低音乐音量，回复结束后恢复用户设定值。音乐播放状态和音量调整须分开，不把临时降低音量记为用户设置。

建议静音结束阈值初值为 800 毫秒、单句上限 30 秒、连续无有效语音 60 秒自动结束。以上是待实测调整的产品初值；空音频、短噪声和误识别片段不能反复触发模型回复。单句达到上限时提交已有内容并提示已分段。

由 Momo 自身的音频模块完成说话检测与分句。参考上游的检测和切句思路，但重新适配双音源及当前应用生命周期；不能只采集音频就认定具备持续聊天能力。

### 6.2 回复与打断

Momo 默认每轮回答 1～3 个短句，先回应用户，再按需轻问一句；不机械重复欢迎词。前后文应能理解“刚才那个”“我前面说的”。人物称呼和音色在会话中保持一致。

收到可播放片段即按顺序播放，不等整篇回答全部生成；显示与当前片段对应的文字。纯文字片段也应展示。模型标记、工具状态和内部提示不能作为对用户的台词播放。

用户开始说话时停止当前声音并取消旧回复，避免两段内容交叠；未播放内容不得作为“用户已听到的回答”回传。常驻屏幕按钮提供手动打断；仅当前选中聊天活动时，旋钮短按才执行聊天的打断或提交动作。其他活动使用旋钮不打断回复。打断后迟到的旧片段不能混入新一轮。

Mac 扬声器外放是主验收场景：Mac 麦克风和键盘麦克风分别要求回声抑制，防止 Momo 识别自己的声音。键盘上传的是自定义音频流，不能假定浏览器麦克风的回声消除设置会自动作用于这路音频；需要拿到播放参考信号并验证处理效果。耳机场景作为辅助测试。如果外放的自然打断未通过，只能明确提供「手动打断模式」作为降级，不能标注为已完整支持自然打断，也不能仅凭耳机通过就完成主场景验收。

### 6.3 文字与养成

文字输入作为明确可用的替代入口，使用项目内同一对话控制器和上下文。用户编辑文字时可暂停语音提交，避免一轮产生两次请求。纯文字模式默认不朗读；重新开启语音后恢复语音播放。

本地预设回复保留为「本地陪伴」模式，界面要明确标识。语音处理模块或所选模型服务故障时不自动用预设回复冒充模型回答，也不自动把同一条输入转发到第二个服务。

一个语音会话只生成一条概述日记，不把每个音频片段写成日记。首版建议至少完成一次有效来回才记录，并最多增加一次心情值，避免分段播放重复触发养成奖励。

## 7. 状态与界面

| 状态 | 用户可见信息 | 音频行为 |
| --- | --- | --- |
| 未开始 | 「按 S5，再按旋钮开始聊天」 | 不采集、不播放 |
| 正在准备 | 「正在准备语音聊天」或权限说明 | 不上传声音 |
| 正在倾听 | 「我在听」及输入电平 | 检测并采集有效发言 |
| 识别 / 思考 | 「让我想想」 | 等待当前轮；保留打断入口 |
| 正在说话 | 回复字幕、Momo 说话动画、打断提示 | 顺序播放，支持打断 |
| 已结束 | 「这次先聊到这里」 | 释放麦克风，清空播放队列 |
| 异常 / 暂停 | 简明原因、重试及文字入口 | 停止当前采集与播放 |

“EasyInput 已连接”“键盘麦克风已就绪”“语音功能已就绪”“麦克风正在使用”分别展示，并始终标出当前收音源是「键盘麦克风」还是「Mac 麦克风」。键盘连接不意味着语音可用，模块初始化也不意味着所选模型可用。

保留现有 Momo 视觉风格与角色形象。首版使用轻量倾听、思考和说话动画；可以参考返回的音量数据驱动节奏，不要求引入 Live2D 渲染或参考项目角色素材。

## 8. 异常、退出与隐私

- 内置语音模块初始化失败：显示具体不可用环节，提供重试、设置和文字入口；不能提示用户去启动 Open-LLM-VTuber。
- 麦克风不可用、权限撤回或输入设备断开：按第 6.1.1 节切换或暂停，不隐藏音源变化。
- 键盘断开：活跃会话按已确认的音源规则转到 Mac；会话已经结束时，恢复连接不自动开麦。
- 所选模型连接断开或回复超时：停止当前轮，保留已确认文字，重试由用户发起；不自动重发导致重复回答。
- TTS 失败：显示已有回复及「语音播放失败」，允许继续文字聊天。
- 用户明确结束聊天、系统睡眠、应用窗口关闭或应用退出：取消会话、停止所有媒体轨道、向键盘发送停止采集命令、停止播放并丢弃过期结果。命令无法送达时键盘必须按采集授权超时自行停止。
- 只在用户显式开始后收音。模块初始化、模型重连或历史恢复都不能自行开启会话。
- 独立实现不等于必须完全离线。Momo 可以直接使用选定的本地模型、模型库或外部 ASR / LLM / TTS 服务；不经过 Open-LLM-VTuber 中转。具体供应商与离线需求尚未确定，设置页应说明各环节的数据去向。
- API 密钥由 Momo 主进程或自身服务层管理，不经硬件、不暴露给普通界面、不显示在错误信息中；持久保存方案在实现前明确。
- 默认不保存原始录音、不持久保存聊天原文。需要覆盖 Momo 界面、主进程、模型适配器和辅助进程的正文日志、临时音频与异常清理，不能只关闭界面的本地存储。
- 首版不自动创建持久化聊天历史；同一次打开期间使用同一逻辑上下文。重连无法恢复时明确提示开启新对话，不能假装记得断线前内容。
- “清空对话”应清除项目各模块的会话上下文和对应缓存；不能只删除屏幕上的气泡。与养成数据重置分开。

### 9.4 键盘麦克风与音频传输要求

板载麦克风 BCLK / WS / DIN 为 GPIO9 / GPIO10 / GPIO11；GPIO11 是 MCU 输入。现有板载操作音使用另一组扬声器引脚，不能用现有 TX 播放任务代替 RX 采集。

- 不要求键盘枚举为系统 USB 麦克风；可通过专用音频协议上传给 Momo。USB Audio Class 属于另一种架构选择，不能把当前 USB Serial/JTAG 说成已有 UAC 设备。
- 建议统一交给识别端的格式为 16 kHz 单声道；线上的 PCM 位宽或压缩编码、板上 I2S 格式与重采样方案需在实现前以器件资料及传输测试确定。
- 以 16 kHz、16 bit、单声道 PCM 估算，净音频速率为 256 kbit/s，即 32,000 字节/秒；20 毫秒音频为 640 字节，另计帧头和传输开销。真正的 115200 baud UART 8N1 只能提供约 11,520 字节/秒，不能直接承担该原始音频。原生 USB Serial/JTAG 与 UART 的速率限制不同，需要分别实测。
- 当前 USB JSON 行上限 512 字符，BLE 是三字节事件通知；不能直接把整段音频塞入原事件。USB 需定义可恢复边界的音频帧及与日志、按键共存策略，BLE 需新增音频与控制特征并处理 MTU 分片、吞吐、缓冲与丢帧。
- 首版包含现有 USB 和 BLE 两种连接下的收音目标。可以先验证 USB，再验证 BLE；BLE 带宽不足时必须评估压缩或更新方案并回到需求评审，不能静默降为 Mac 麦克风后声称满足需求。
- 新增协议至少表达：麦克风能力、采样格式、开始采集、开始确认、停止采集、停止确认、音频帧序号、采样时间、丢帧统计、采集错误和会话标识。命名属于后续协议设计，不能冒充上游现有接口。
- 音频队列必须有界。持续积压时提示音频异常，不能延迟数秒补播、吞掉 S5 或拖延停止命令；半句损坏时请求重说。
- 只在有效会话授权期间采集和上传。停止命令目标 500 毫秒内生效；连接丢失或授权心跳停止后，键盘目标 2 秒内自行结束采集。不能依赖电脑永远正常退出。
- GPIO8 由 LED、麦克风、扬声器共享。停麦不等于关闭 GPIO8；启停必须协调现有操作音和其他消费者。麦克风 RX、扬声器 TX 的 I2S 资源、时钟、内存和电源稳定条件需要独立验证。
- 板载操作音可能直接被板载麦克风录入，应通过采集时序、去噪或回声处理避免误触发。若必须临时抑制操作音，需要明确会话级规则，并在结束后恢复用户原设置。

## 10. 性能与验收标准

以下为拟定目标，全部待验证。延迟在 Momo 语音模块已就绪、模型已预热、权限已批准的条件下测量；冷启动单独记录。记录电脑、输入输出设备、模型配置及网络条件。正常语音至少采样 20 轮，报告中位数和 P95。

| 验收场景 | 通过条件 |
| --- | --- |
| 项目独立性 | 在未安装、未启动 Open-LLM-VTuber 的干净环境安装 Momo，仅配置本项目选定的模型与必要资源即可完成语音对话；运行时无对该项目服务、文件或配置的访问 |
| 两步开始 | 单按 S5 仅选择聊天，200 ms 内反馈，无采集或上传；旋钮确认后，预热情况下 1 秒内进入可收音状态；重复选择不创建第二会话 |
| USB / BLE | 两种连接分别进行 20 次 S5 选择、旋钮确认与明确结束，无重复会话；真实 S5 和旋钮触发分别留证 |
| 无键盘收音 | 通过屏幕开始，Mac 麦克风采集，Mac 扬声器回答，完整完成 10 轮 |
| 有键盘收音 | USB、BLE 分别验证实际来自板载麦克风；Mac 麦克风不采集，回答仍从 Mac 出声，不能仅凭设备名称判定 |
| 音源切换 | 会话中连接、断开键盘各 10 次，按规则提示并切换；未提交半句不跨设备拼接，旧音频不混入 |
| 旧固件 / 音频故障 | 按键可用但麦克风无能力、无帧或丢帧时明确报告，不静默伪装为键盘收音 |
| 连续聊天 | 连续 10 轮无需逐句按键，后续问题能引用前文 |
| 中文识别 | 安静环境的 20 条日常句子，至少 18 条关键语义正确；口音和噪声另记结果 |
| 响应速度 | 话音结束到第一段可听回复，中位数目标不超过 3 秒，P95 目标不超过 5 秒；包含静音分句时间 |
| 反馈与超时 | 等待超过 5 秒显示明确状态；30 秒仍无有效输出时结束等待并允许重试 |
| 手动打断 | 点击打断按钮或在聊天活动下短按旋钮，300 ms 内停止可听播放，无旧片段补播；其他活动短按旋钮不触发打断 |
| 自然打断 | Mac 扬声器外放下，Mac 麦克风与键盘麦克风分别测试 10 次，检测有效语音后 500 ms 内停播，无误听自己；耳机仅作辅助 |
| 回复完成 | 合成完成但仍有音频未播完时，不标记本轮结束；全部片段实际播放完毕后才完成本轮 |
| 明确退出 | 常驻结束按钮、聊天活动下长按、关闭应用窗口分别测试；500 ms 内停止应用采集与播放；切换活动或收起聊天面板不误退出 |
| 键盘采集退出 | 正常停止目标 500 ms 内生效；强退应用、断线及停止授权心跳后 2 秒内键盘自行停采，采集不可持续残留 |
| 前后台 | 后台或最小化时按 S5 恢复窗口并选中聊天，不立即收音；再按旋钮才开始；已有会话恢复时不重开；应用退出不承诺唤起 |
| 权限及故障 | 拒绝麦克风、断开输入设备、模块初始化失败、模型连接断开、断键盘、断网、TTS 失败均有可恢复提示，无重复请求 |
| 稳定性 | 连续使用 15 分钟，无声音叠加、队列积压、误听自己或无法退出 |
| 隐私 | 未开始时无麦克风轨道；会话结束后轨道释放；项目所有模块默认无新增持久聊天原文或遗留原始录音 |
| 活动与聊天并行 | 倾听、思考、播音三种状态下分别操作 S1～S4、S6、S7：每次选择、旋转与确认均执行原动作，聊天会话号和上下文保持不变，无误打断或重复输入；S8 单独选择不结束，确认睡眠按已评审规则验证 |
| 聊天视图 | 收起面板后仍可操作其他活动，收音来源与结束按钮持续可见；活动反馈不覆盖字幕 |
| 原功能回归 | 其他七键、旋钮选择确认、睡眠、音乐、日记和键盘操作音按本稿明确变更后的规则正常工作 |

先用电脑端模拟验证输入路由、双音源切换、音频协议、重复触发、取消、超时与音频队列；再测项目自身语音模块、选定模型以及打包应用的麦克风、扬声器、权限。固件新增采集逻辑先进行宿主测试和构建，后续获得用户明确烧录授权后，再记录实板收音、USB / BLE 传输、外放回声和 S5 的结果。需求评审阶段未进行构建或验证；后续用户已授权开发，已完成电脑侧测试与构建。实板写入仍需单独授权，真实语音目标尚未全部验收。
