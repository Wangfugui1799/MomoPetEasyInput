# Momo · EasyInput 桌面宠物

**八颗按键，一个旋钮，和你一起过普通的小日子。**

一款面向 Mac 的桌面陪伴原型，使用 EasyInput 键盘与薄荷绿色的 Momo 互动。支持喂食、摸摸、训练、探索、聊天、装扮、音乐和睡觉；没有硬件时，也可以用鼠标和电脑键盘体验。

## 项目特点

- **固定八键，旋钮扩展**：按键选择活动，旋转预览具体选项，按下确认执行。
- **轻度养成**：饱腹感、心情、体力和亲密度随互动变化，休息时恢复体力。
- **有反馈的小日常**：基础动画、帽子装扮、随机散步事件和节奏训练小游戏。
- **本地陪伴记录**：保存宠物状态、已确认的装扮和最近 200 条日记，支持导出 Markdown。
- **可选 AI 对话**：默认提供明确标注的本地预设回复；填写自己的服务配置后启用真实 AI。
- **桌面窗口与音乐**：支持 Mac 窗口置顶，三首程序合成的轻音乐从电脑播放。

这是可运行的开发原型。0.1.0 曾验证固件烧录、应用启动握手与桌面端实际连接；0.2.0 操作音效已完成烧录、正常启动和设备设置读取，用户已初步认可使用效果，实体按键完整功能矩阵仍待验收。

## 快速开始

### 环境要求

| 用途 | 要求 |
| --- | --- |
| 桌面应用 | Node.js 22+、npm；已在 Apple Silicon Mac 上验证 |
| 浏览器预览 | 现代桌面浏览器；连接硬件需要支持 Web Serial 的 Chrome / Edge |
| 配套硬件 | EasyInput V2.0，PCB 丝印 AI Keyboard V2.1，ESP32-S3、16 MB Flash |
| 固件构建 | ESP-IDF 5.5.5，已安装 ESP32-S3 工具链 |

### 启动桌面应用

下载或克隆本仓库，进入包含 `package.json` 的目录后运行：

```sh
npm ci
npm start
```

Momo 会打开独立桌面窗口。首次启动不需要开发板或 AI 密钥：点击底部活动键，再用右侧旋钮选择和确认，就能体验。

### 仅预览界面

```sh
npm run dev
```

打开 [http://127.0.0.1:4783](http://127.0.0.1:4783)。桌面应用使用本机端口 `4784`，浏览器预览默认使用 `4783`；两者的宠物存档彼此独立。

### 构建 Mac 应用

```sh
npm run package:mac
```

生成的应用位于 `dist/Momo-darwin-arm64/Momo.app`。`dist/` 不包含在 Git 源码中，克隆仓库后需要自行构建。

当前打包脚本面向 Apple Silicon。Intel Mac 可另行构建 x64 版本，尚未实测：

```sh
npx electron-packager . Momo --platform=darwin --arch=x64 --out=dist --overwrite --extend-info=desktop/Info.plist --ignore='^/(firmware|tests|test-results|docs|dist|scripts|playwright.config.mjs)'
```

应用尚未进行 Developer ID 签名和公证，目前验证范围为本机运行。

## 麦克风语音聊天

先启动本机 Open-LLM-VTuber（`127.0.0.1:12393`）。在设置的「语音输入」中选择系统默认麦克风、具体电脑麦克风或 EasyInput 板载麦克风，选择会保存为默认。然后按 S5，转动旋钮选择「语音聊天」，短按旋钮开始。选择「文字聊天」只打开聊天框，也可随时点击输入框左侧的麦克风开关。

EasyInput 板载麦克风需要 **0.5.0 固件及原生 USB Serial/JTAG 连接**，UART 桥接和 BLE 不传音频。断线或设备不可用时会停止并提示，不会偷偷切换到电脑麦克风。切换设置中的输入会停止当前语音，下次开始使用新音源。回复仍从电脑播放。

0.5.0 已完成电脑测试、模拟 USB 音频的真实 VAD／VTuber 三轮验证与 ESP-IDF 构建；**已完成本版应用区烧录并通过数据校验；重启运行和板载麦克风实板收音仍待验证**。详见 [键盘语音输入说明](docs/KEYBOARD-VOICE-INPUT.md)。

- 说完停顿约一秒，自动识别文字并生成回答，使用 VTuber 当前 TTS 声音播放。
- 「正在想／正在说」时暂停接收下一句话；恢复「正在听」后继续说，无需重复打开。
- 关闭聊天窗口或按 Escape 后仍可继续语音聊天；主界面显示语音状态，可查看对话或关闭麦克风。点击关闭麦克风或退出应用才停止采集与播放。一次说话最多一分钟，不支持抢话。
- 麦克风开启时，文字发送也走 VTuber；关闭后恢复原来的本地预设／已配置 AI 文字聊天。
- 语音识别走本机后端；识别文字及对话由 VTuber 配置的 AI 服务处理，VTuber 会保存历史。角色性格、模型和 TTS 声音沿用后端当前配置。

VAD 模型、ONNX Runtime 和工作线程均从本地依赖加载，无需 CDN。电脑麦克风授权失败时，请检查 macOS「系统设置 → 隐私与安全性 → 麦克风」。开发模式可能显示为 Electron，打包后显示为 Momo。

[语音验证记录](docs/VOICE-CHAT-VALIDATION.md)区分了自动化验证和真人收音验收。

## 八键与旋钮

**按键选择活动 → 旋转选择选项 → 按下旋钮执行。** 旋转预览不会直接完成喂食、换装等动作。

| 按键 | 活动 | 旋钮选择 | 确认后的行为 |
| --- | --- | --- | --- |
| S1 | 🍪 喂食 | 曲奇 / 草莓 / 牛奶 | 增加饱腹感；吃饱后不继续获得奖励 |
| S2 | 🤏 摸摸 | 摸头 / 拥抱 / 按摩 | 增加心情与亲密度 |
| S3 | 🎯 训练 | 三档难度 | 开始小游戏，光点进入绿色区时再次按下 |
| S4 | 🧭 探索 | 窗边花园 / 云朵小径 / 星光池塘 | 消耗体力，产生随机事件；两次探索至少间隔 30 秒 |
| S5 | 💬 聊天 | 语音聊天 / 文字聊天 / 关闭麦克风 | 按下旋钮执行所选功能；S5 本身只选择活动 |
| S6 | 🎩 装扮 | 原样 / 礼帽 / 花朵 / 派对帽 | 保存当前装扮；旋转时仅预览 |
| S7 | 🎵 音乐 | 云端钢琴 / 午后风铃 / 晚安星河 | 播放，再次确认同一首时停止 |
| S8 | 🌙 睡觉 | 三种休息选项 | 切换睡眠 / 唤醒；当前选项共享相同休息逻辑，无定时闹钟 |

- **旋钮长按 600 ms**：关闭弹出面板，或取消当前训练 / 选择。
- **方向反转**：在设置中开启“旋钮方向反转”，适配实际操作习惯。
- **睡眠期间**：先选择 S8 并确认唤醒，再进行其他活动。“睡觉”是宠物状态，不是开发板深睡眠。

没有硬件时的操作：

| 输入 | 功能 |
| --- | --- |
| 数字 `1`–`8` | 选择对应活动 |
| `←` / `→` | 切换具体选项 |
| `Enter` | 确认；焦点位于按钮或链接时执行该控件的默认操作 |
| `Esc` | 关闭弹出面板，或取消训练 / 当前选择 |
| 屏幕旋钮上的鼠标滚轮 | 切换具体选项 |
| 屏幕上的 `−` / `＋` | 切换具体选项 |

## 连接开发板

### 1. 构建专用固件

Momo 使用自己的串口事件协议，**不能直接使用普通 USB HID 键盘固件代替**。烧录此固件会替换键盘原有固件。

安装并激活 ESP-IDF 5.5.5。下面的 `/path/to/esp-idf` 是占位路径，需要替换为本机的实际安装目录：

```sh
source /path/to/esp-idf/export.sh
idf.py --version
idf.py -C firmware -B "$PWD/firmware/build-ble" -D SDKCONFIG="$PWD/firmware/build-ble/sdkconfig" build
```

目标芯片和 Flash 容量已在 `firmware/sdkconfig.defaults` 中设置。构建产物包括：

| 产物 | 作用 |
| --- | --- |
| `firmware/build-ble/bootloader/bootloader.bin` | 启动程序 |
| `firmware/build-ble/partition_table/partition-table.bin` | 分区表 |
| `firmware/build-ble/momo_easyinput.bin` | Momo 应用 |

### 2. 写入并恢复正常启动

先确认目标设备的芯片、MAC 和待覆盖的固件。以下 BOOT 操作只适用于本项目对应的 EasyInput 开发板：

1. 保持键盘开机，**短按并松开一次 BOOT**，进入下载模式。
2. 重新查看串口列表并核对设备身份，不能只按端口名称判断是哪块板。
3. 在已激活的 ESP-IDF 环境中执行以下命令。将 `MOMO_PORT` 替换为本次实际确认的端口，不要照抄示例端口。

   ```sh
   MOMO_PORT=/dev/cu.usbmodemXXXX
   idf.py -C firmware -B "$PWD/firmware/build-ble" -D SDKCONFIG="$PWD/firmware/build-ble/sdkconfig" -p "$MOMO_PORT" flash
   ```

4. 写入完成后，使用板上电源开关**关机，再开机**，恢复正常运行；不要再次按 BOOT。
5. 继续确认应用握手。写入哈希校验成功，仅代表数据写入正确，不等于应用已经启动。

本固件写入启动程序、分区表和应用，不要求整片擦除。具体偏移以本次构建生成的 `firmware/build-ble/flash_args` 为准。

### 3. 在 Momo 中连接

打开应用，点击右上角“连接 EasyInput”，选择运行 Momo 固件的串口。原生 USB 设备可能显示为 `USB JTAG/serial debug unit`；名称只用于定位候选，应用还会等待协议握手。

成功后，界面显示 **EasyInput 已连接**。连接不会自动完成，断开后需要再次点击连接；同一串口请只交给一个应用使用，先关闭占用它的串口监视器或其他 Momo 页面。

固件每 2 秒发送一次握手：

```json
{"protocol":"momo-easyinput/1","type":"hello","board":"easyinput-v2","firmware":"0.2.0","sound":true,"dropped":0}
```

应用在首次连接的 5 秒内等待握手，收到前忽略控制事件；连接后若持续收不到心跳，会提示重新连接。串口握手用于确认协议兼容性，不代替烧录前的设备身份核对。

### 蓝牙控制与电量（0.4.0）

安装新版 Momo 应用并写入 0.4.0 固件后，保持键盘开机，在 Momo 中点击 **蓝牙连接**，选择 **Momo EasyInput**。首次使用需允许 macOS 的蓝牙权限。此设备使用 Momo 专用 BLE 服务，从应用内连接，无需先在系统设置里配对为普通键盘。

支持 S1–S8、旋钮双向旋转、短按和长按。断开后设备重新广播，可再次连接；同一时间只连接一台蓝牙主机。应用一次选择 USB 或蓝牙，切换前点击连接状态断开。键盘本机音效保留，音量与开关设置仍需 USB。

连接后，应用会在顶部显示键盘电量。开发板没有专用电量计，百分比由电池电压估算；本版已完成固件写入、正常启动、真实蓝牙连接和 96% 电量上报验证。详细记录见 [蓝牙验证记录](docs/BLUETOOTH-VALIDATION.md) 和 [电量验证记录](docs/BATTERY-STATUS.md)。

### 硬件映射

| 资源 | GPIO |
| --- | --- |
| S1–S8 | `2 / 47 / 38 / 41 / 1 / 6 / 7 / 48` |
| 编码器 A / B / 按压 | `17 / 16 / 18` |
| 原生 USB D− / D+ | `19 / 20`，由 USB 外设使用 |
| UART0 TX / RX | `43 / 44`，需按实际接线使用 |

固件同时向原生 USB Serial/JTAG 和 UART0（115200）输出事件。八键、编码器相位和按压由固件处理，电脑应用负责养成状态与界面。每四次有效正交相位跳变产生一个旋转事件；实际每格步数和转向仍需实板确认。

0.2.0 新增键盘本机操作音效：八键按下、旋钮转动与按压各有轻短音，默认开启、30% 音量。连接新版固件后，在设置中调整“键盘操作音效”和“操作音量”，设备确认保存后断电仍保留；可点击“键盘试听”。电脑音乐音量与键盘音量分别设置。

固件增加扬声器 I2S 输出，GPIO8 在安全初始化后开启，静音不会切断共享电源。该音效版本尚未启用板载 LED 或麦克风；0.5.0 新增麦克风 USB 上行，尚未实板验证。新版已完成电脑验证、构建、烧录、正常启动及设备音效状态读取，用户已初步认可使用效果；电源稳定条件、音量范围与外设共存仍需完整实板验收。详见 [操作音效验证记录](docs/INPUT-SOUND-VALIDATION.md)。

完整事件格式与硬件边界见 [协议文档](docs/PROTOCOL.md)。

## AI 对话

默认模式为 **“本地陪伴 · 预设回复”**，不调用外部模型。要使用真实 AI，在设置中填写：

| 配置 | 内容 |
| --- | --- |
| 完整接口地址 | 兼容 Chat Completions 的 HTTPS 地址，例如 `https://api.deepseek.com/chat/completions` |
| 模型名称 | 服务商当前提供且你的账号有权使用的模型 |
| API 密钥 | 你自己的服务密钥 |

点击“使用 AI 对话”后，下一条消息会尝试调用服务；保存配置本身不会测试连接。也可以随时选择“恢复本地陪伴”。外部服务的可用性、费用和模型兼容性由服务商决定，本项目不附带调用额度。

### 数据保存与发送范围

- **保存在本机**：宠物状态、确认后的装扮和最多 200 条日记。日记可导出，也可在设置中清除。
- **仅保留在本次打开期间**：聊天正文、AI 配置和密钥。密钥不写入 `localStorage`，关闭应用后需要重新填写。
- **启用 AI 后发送**：最近最多 12 条消息、宠物心情和体力，以及 Momo 的角色提示，发往你填写的服务地址。
- **日记中的聊天记录**：只记录“聊了一会儿”，不保存聊天原文。

本地服务只监听 `127.0.0.1`，桌面渲染层关闭 Node 集成。项目没有云端账号和跨设备同步。

## 项目结构

```text
.
├── app/                    # 界面、宠物状态、串口协议、合成音乐
├── desktop/                # Electron 窗口、设备选择、权限与置顶
├── firmware/
│   ├── main/               # GPIO 采样、消抖、编码器、事件发送
│   ├── tests/              # 可在电脑运行的 C 输入逻辑测试
│   └── sdkconfig.defaults  # ESP32-S3 默认构建配置
├── tests/                  # 状态、协议、服务端与界面测试
├── scripts/                # 打包后桌面应用启动检查
├── docs/                   # 截图、协议、构建与实板验证记录
├── server.mjs              # 本地静态服务与 AI 请求转发
└── package.json            # 应用命令与依赖
```

交互数据流：实体按键 / 旋钮 → 固件输入处理 → USB 串口事件 → Momo 应用 → 宠物状态、动画与日记。AI 服务是电脑端的可选能力，开发板不保存密钥或聊天内容。

## 常见问题

**没接键盘，可以先运行吗？**

可以。鼠标、数字键和方向键可以体验本地功能。

**选择端口后提示没有 Momo 握手？**

检查是否写入本项目固件、是否已恢复正常开机、是否选对端口。普通 HID 固件和 ROM 下载模式都不会发送 Momo 应用握手。

**提示端口被占用？**

关闭串口监视器，或断开另一个浏览器 / 桌面 Momo 的连接，再重试。

**旋钮方向与习惯相反，或每格步数不对？**

方向可在设置里反转。每格步数需要结合实际编码器相位确认，再调整固件解码规则。

**聊天为什么像固定回答？**

默认是本地预设陪伴。需要在设置中配置自己的 AI 服务后，才会调用真实模型。

**键盘上的灯和扬声器没有反应？**

板载灯光尚未启用。键盘操作音效需要 0.2.0 固件，旧版固件不会发声；新版已烧录并报告音频驱动就绪，用户已初步认可使用效果，逐项功能验收尚未完成。电脑音乐仍从电脑播放。

## 当前范围与后续方向

当前以八键互动、基础养成和可运行的桌面窗口为核心。尚未实现：透明桌面挂件、开机自启、全局快捷键、板载灯光与语音播放、云同步、自动更新、签名和公证发布。

后续可优先完善实体功能矩阵、旋钮手感、断连恢复和 AI 服务实测，并完成板载麦克风实体验收，再扩展桌面挂件。
